# Лабораторная: Пошив шляп с браком и переделкой (SimLab)

## Цель
Изучить дискретно-событийную модель потока заказов с браком и переделкой, оценить удовлетворённость клиентов (выполненные / поступившие), сравнить базовую схему на готовых блоках и улучшенную схему с пользовательскими блоками.

## Исходные данные
- Межприбытия заказов: 3±1
- Пошив-1: 5±1
- Контроль качества: брак с вероятностью K% (K = 0, 5, 10, 20, 33, 50)
- Пошив-2 (переделка): 2±1, вероятность брака 0%
- Время моделирования: 480 (можно 960)

## Метрики
- Поступившие: `Source.total_in`
- Выполненные: `Sink.total_out`
- Удовлетворённость: `Sink.total_out / Source.total_in`
- Очереди: длина/среднее для буферов
- Загрузка серверов: utilization
- (опц.) Доля переделок, средний lead time — можно добавить в Custom-блок метрики

---
## Этап 1. Базовая схема на готовых блоках (две очереди)
**Схема:**
1. Source (3±1)
2. Queue-1
3. Server «Пошив-1» (5±1)
4. Branch «Контроль качества» (вероятность брака K%)
   - good → Sink «Готово»
   - reject → Queue-2 → Server «Пошив-2» (2±1) → Branch «Контроль» (0%) → Sink

**Шаги:**
1. Соберите схему в редакторе, задайте распределения.
2. Прогоните сценарии K = 0/5/10/20/33/50 (симвремя 480 или 960).
3. Для каждого прогона зафиксируйте метрики.
4. Постройте график «K% → удовлетворённость», сравните очереди и загрузки серверов.

---
## Этап 2. Улучшенная схема с кастомными блоками
Добавляем три своих блока (пример реализации — в Custom):
- **Inspector** — ставит `defect=True/False` по вероятности K%, может писать `attempt`.
- **CustomBranch** — маршрутизация по атрибуту заявки (`defect`), а не по вероятности.
- **PriorityQueue** — очередь с приоритетами (браку — высокий приоритет).

**Схема:**
1. Source → PriorityQueue → Server «Пошив-1» → Inspector (K%) → CustomBranch:
   - defect=False → Sink
   - defect=True → PriorityQueue (тот же или отдельный, но с высоким приоритетом) → Server «Пошив-2» → Inspector (0%) → CustomBranch → Sink

**Шаги:**
1. Реализуйте логику трёх блоков в Custom (или добавьте новые типы по желанию).
2. Снова прогоните K = 0/5/10/20/33/50.
3. Сравните с Этапом 1: выпуск, очереди, загрузки, долю переделок.

---
## (Опционально) RL-контур
- Наблюдения: длины очередей (основной/переделка), загрузки серверов.
- Действия: выбор политики приоритета (например, {обычно, всегда брак первым, стоп новых заявок}) или выбор маршрута для брака.
- Награда: `+выпуск − α*(len_main+len_rework)`; α подобрать.
- Эпизод: 480–960, шаг 20. Агент: Q-learning/DQN (шаблоны уже есть).
- Сравнить с статическими политиками.

## Отчёт

3. График «K% → удовлетворённость» (для обоих этапов).
4. Выводы: как брак влияет на выпуск; что даёт отдельная ветка/приоритеты; есть ли выигрыш от кастомной логики/приоритетов (и RL, если делали).
